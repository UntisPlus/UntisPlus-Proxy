Setup & Onboarding

Configure this instance for real-world use. Fresh installs should start here: fix trusted proxy/real client IP detection, define access roles, add notification links, and manage users/admins.

1. Real client IPs (trusted proxies)

If this server is behind a reverse proxy or load balancer, trust that proxy so X-Forwarded-For/X-Real-IP are honored for the real client IP (used for rate limiting and logging). Leave empty when directly exposed.

2. Roles & access control

Create capability groups and grants, role defaults, and person-type mappings. Control who can access pooled, reconstructed, boosted/raw, ntfy/webhook, calendar, and other capabilities without relying on legacy role defaults.

3. Notifications & alerts

Add ntfy topics, webhook subscriptions, and outage alert destinations so operators and users receive timetable/change/outage notifications.

4. Users & admins

Promote admins, review signed-in users, and configure default permissions for newly seen users where appropriate.

Trusted reverse proxies & client IP diagnostics

Save trusted proxy IPs/CIDRs (comma-separated). The server will only honor forwarded client IP headers from trusted peers. Use the live diagnostics below to confirm the resolved client IP when accessing through your reverse proxy.

Examples: a single reverse proxy IP, your Docker/proxy network CIDR, or localhost entries. If left empty, forwarded headers are not trusted and the direct peer IP is used.

Access checklist

Recommended baseline after first login.

  • Verify trusted proxy/client IP resolution if behind a reverse proxy.
  • Review/create capability groups and role defaults for your school/users.
  • Set person-type → role mappings if needed for your Untis setup.
  • Inspect effective access for key users and adjust grants/gates.
  • Configure ntfy/webhook/outage destinations and add additional admins.
  • Mark onboarding complete when finished.
