Overview

A clear starting point for your instance. Follow guided onboarding to configure real client IP handling, add a school, create the first admin/user, define permission groups, and onboard more users.

Recommended first-run flow

Complete these steps in order for a clean, production-ready setup.

  1. Proxy & real client IP: configure trusted proxies if behind reverse proxy/load balancer.
  2. Add a school: register the Untis school this instance should serve.
  3. First user/admin: have the operator provision the intended administrator, then sign in.
  4. Permission groups & roles: define capability groups, role defaults, and mappings.
  5. Add other users: promote/manage users and fine-tune permissions.
  6. Notifications: add ntfy/webhooks/outage alerts, then mark onboarding complete.

Proxy & Real Client IP

Review

If this instance runs behind a reverse proxy or load balancer (Cloudflare Tunnel, Traefik, nginx, etc.), configure trusted proxy IPs/CIDRs so X-Forwarded-For/X-Real-IP are only honored from trusted peers. This ensures correct real client IPs for rate limiting and logs.

Trusted proxy configuration

Comma-separated IPs/CIDRs. Leave empty when directly exposed. Save, then reload through your proxy to verify the resolved client IP.

Authentication methods — all accounts
Shows whether this proxy has a saved token/shared secret, a saved upstream password, both, or neither. Token here means the reusable app shared secret, not a one-time authenticator code. Stored does not mean recently tested.
AccountSchoolLinked peopleSaved authenticationBackground fetching

        
Why can login work but timetable fetching fail?
A one-time code proves the person can sign in now. Background fetching needs a reusable password or shared secret, which some app login flows do not send.
Ask the person to complete the app’s normal account setup through this proxy, including the QR/shared-secret enrolment step. Then refresh this page. Do not paste passwords, authenticator codes or shared secrets into support messages.
A missing class or unclear person type may be normal for a parent or an account without a linked school person. Review upstream identity before changing its permissions; do not assume it is a student or teacher.
